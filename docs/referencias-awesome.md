# Referencias editoriales

Tomamos ideas de repositorios Awesome consolidados, sin copiar sus textos ni convertir el número de estrellas en un criterio técnico.

| Referencia | Práctica adoptada aquí |
|---|---|
| [awesome / manifiesto](https://github.com/sindresorhus/awesome/blob/main/awesome.md) | Selección curada, badge oficial y guía de contribución. |
| [awesome-python](https://github.com/vinta/awesome-python) | Portada orientada a lo que el lector quiere hacer y categorías fáciles de recorrer. |
| [awesome-python / CONTRIBUTING](https://github.com/vinta/awesome-python/blob/master/CONTRIBUTING.md) | Criterios explícitos de calidad y documentación antes de añadir enlaces. |
| [awesome-selfhosted](https://github.com/awesome-selfhosted/awesome-selfhosted) | Separación entre índice, descripciones y reglas para aportaciones. |

## Decisiones para automatización industrial

- Un README atractivo no convierte una propuesta en un bloque usable: el enlace debe llevar a un archivo real y a su evidencia.
- La compatibilidad se declara por versión de TIA y familia de CPU/HMI probadas, nunca por apariencia del código.
- Una compilación sin errores no acredita comportamiento de proceso. Se documentan por separado pruebas en PLCSIM y Runtime HMI.
- No se publican proyectos de cliente, nombres de máquina, rutas personales, credenciales ni capturas con información sensible.
- Las imágenes conceptuales se distinguen de capturas reales y resultados de pruebas.
